# 사업계획 예상손익 (biz-plan)

재무팀이 쓰던 **「사업계획용 예상손익 자료작성.html」** 을 사내 포털에 붙인 것입니다.
**화면과 계산 결과는 원본 그대로**이고, 달라진 것은 계산하는 자리뿐입니다.

| | 원본 | 이 앱 |
|---|---|---|
| 계산하는 곳 | 브라우저 (Pyodide) | 이 컨테이너 |
| 파이썬을 어디서 받나 | cdn.jsdelivr.net · pypi.org | **안 받음** (이미지에 들어 있음) |
| 사내망에서 막히면 | 첫 화면에서 멈춤 | 해당 없음 |
| 계산 시간 | 0.4초 | 0.4초 (같은 코드) |

`app/engine.py` 는 원본 HTML 안에 있던 **976줄을 한 줄도 바꾸지 않고** 옮긴 것입니다.
숫자가 달라지면 안 되기 때문입니다. 값 9,436개를 원본과 대조해 **전부 일치**를 확인했습니다.

## 새로 붙인 것 — 입구 점검 (`app/precheck.py`)

이 앱의 위험은 **「틀렸는데 표는 멀쩡히 나오는 것」** 입니다.
채널 이름 하나가 어긋나면 그 채널 매출이 통째로 빠지는데 아무 표시가 없습니다.

실제로 원작자가 준 **예시 파일이 9천만 원을 흘리고 있었습니다.**
매출목표의 `신규채널A` 가 마스터 고객그룹의 `신규에요` 와 이름이 달라 계산에서 빠졌습니다.

그래서 결과를 보여 주기 **전에** 확인하고, 걸리면 **숫자를 아예 안 보냅니다.**
표를 보여 주면 사람은 그 표를 믿기 때문입니다.

핵심은 **파일이 스스로 적어 둔 합계와 계산 결과를 맞춰 보는 것**입니다.
이름이 어긋나든, 열이 밀리든, 수식 값이 저장 안 됐든 — 「뭔가 빠졌다」는 사실은
이 대조 하나로 다 드러납니다.

| 상황 | 화면에 뜨는 말 |
|---|---|
| 두 파일 자리 바뀜 | 자리가 바뀐 것 같습니다. 바꿔 올려 주세요 |
| 엑셀이 아님 | 엑셀 파일이 아닌 것 같습니다 |
| 시트 없음 | 「고객그룹」 시트가 없습니다 (있는 시트: …) |
| 숫자를 못 읽음 | 엑셀에서 한 번 열어 저장한 뒤 다시 올려 주세요 |
| **합계 안 맞음** | 얼마가 왜 빠졌는지 + 어떻게 고치는지 |
| 다 맞음 | 매출 합계 확인 — 파일과 계산이 일치합니다 |

## 파일 보관

**하지 않습니다.** 받아서 메모리에서 처리하고 버립니다. `data` 볼륨도 없습니다.
남는 것은 포털로 보내는 실행 이력(누가 언제 돌렸는지)뿐입니다.

## 처음 띄우기

```bash
docker network create demo-net      # 처음 한 번만
cp .env.example .env                  # ../setup.sh 가 대신 해 줍니다
docker compose up -d --build
```

띄운 뒤 **포털 관리자 화면에서 접근 범위를 정하고 켜야** 직원에게 보입니다.
앱이 스스로 켤 수는 없습니다.

## API

| 주소 | 하는 일 |
|---|---|
| `GET /api/health` | 살아 있는지 |
| `GET /api/me` | 포털이 붙여 준 사용자 정보 |
| `POST /api/run` | 두 파일 → 점검 + 계산 |
| `POST /api/recompute` | 화면에서 고친 값으로 다시 계산 |
| `POST /api/export` | 엑셀 3개 (고객그룹별 · 브랜드별 · CC배부현황) |
| `POST /api/analyze` | 챗 통로 (요약만). 서비스 토큰 필요 |

## 고칠 때

`app` 폴더가 볼륨으로 붙어 있습니다. 파일을 고치고 `docker restart biz-plan` 이면 됩니다.
재빌드는 `requirements.txt` 를 바꿨을 때만 필요합니다.
