# 매뉴얼 · 체크리스트 붙이기

옛 포털(`it-portal/portal-web`)에 있던 정적 화면을 그대로 옮겨 왔습니다.
파일은 이미 `it-guide/web/` 에 복사돼 있습니다 (186개, 17MB).

## 1. 띄우기

```powershell
.\deploy.ps1 it-guide proxy portal
```

`proxy` 도 같이 올려야 합니다 — 새 경로 세 개(`/manual/`, `/checklist/`,
`/ito-cost/`)가 `proxy/apps/` 에 추가됐기 때문입니다.

## 2. 포털에 서비스 등록 — **저절로 됩니다**

띄우면 세 서비스가 관리자 화면에 알아서 나타납니다. 손으로 만들지 않아도 됩니다.

| 서비스 ID | 이름 | 주소 |
|---|---|---|
| `manual` | IT 매뉴얼 | `/manual/` |
| `checklist` | IT 운영 체크리스트 | `/checklist/` |
| `ito-cost` | ITO 비용처리 | `/ito-cost/` |
| `prompt` | 바이브코딩 프롬프트 생성기 | `/prompt/` |

다른 앱들은 자기 코드에서 등록을 보내는데, 이 앱은 **백엔드가 없어서**
보낼 코드가 없습니다. 그래서 한 번 뛰고 끝나는 작은 컨테이너(`guide-register`)를
같이 둡니다. 세 개를 등록하고 스스로 멈춥니다. 확인은:

```powershell
docker logs guide-register
```

```
포털에 서비스 등록
  OK  IT 매뉴얼
  OK  IT 운영 체크리스트
  OK  ITO 비용처리
  OK  바이브코딩 프롬프트 생성기
```

`403` 이 보이면 `AUDIT_TOKEN` 이 포털 것과 다른 겁니다. `setup` 을 다시 돌리세요.

### 그래도 접근 범위는 손으로 정해야 합니다

등록은 **꺼진 상태**로 들어옵니다. 앱이 스스로 켤 수는 없습니다 —
그러면 앱을 올린 사람이 곧 권한을 정하는 사람이 되니까요.

관리자 화면 → 서비스 관리 → 각 서비스의 **접근 범위 설정** → 정하고 **켜기**.

**체크리스트는 좁게 잡으시길 권합니다.** 유지보수 업체 계약 기간과
담당자 연락처가 들어 있어서 전 직원이 볼 내용은 아닙니다.
매뉴얼은 전 직원이어도 괜찮습니다.

## 3. 챗에서 되는 것

권한이 있는 사람에게만 도구가 보입니다.

```
"SAP 신규 엔트리 추가 어떻게 해?"
  → SAP GUI 매뉴얼 · Menu 2 — 그 절차 글자 그대로 + 바로가기

"무슨 매뉴얼 있어?"        → 11개 목록과 각 항목

"월간에 뭐 해야 해?"       → 15개 항목 (SAP 운영 보고, 비용 정산 …)
"인수인계 받았는데 뭐부터"   → 주기별 59개 항목
"유지보수 업체 어디야?"     → 대성ITS · 계약 2025.03~2027.02
```

## 4. 내용 고치기 (지금 방식 그대로)

바뀐 것이 없습니다. 다만 **덮어쓸 자리가 달라졌습니다.**

**매뉴얼**

1. `/manual/` 에서 오른쪽 위 `편집 모드`
2. 고치고 `저장 (manuals.js 받기)`
3. 받은 파일을 `it-guide/web/manuals/data/manuals.js` 에 덮어쓰기
4. 새로고침 — 끝입니다

이미지를 추가할 때는 `it-guide/web/manuals/images/<매뉴얼id>/` 에 파일을
넣고, 편집 모드에서 `sap-gui/02_1.jpg` 처럼 경로를 적습니다.

**체크리스트** — 같은 방식이고, 덮어쓸 자리는
`it-guide/web/checklist/index.html` 입니다.

**프롬프트 생성기** — 화면에서 고치는 기능은 없습니다. 파일 안의
`RULES` 배열이 회사 표준 규칙이고, 그것만 고치면 전 직원에게 반영됩니다.
고칠 때 `RULES_VERSION` 도 함께 올리세요 — 만들어지는 프롬프트와
README 에 그 값이 그대로 남아서, 나중에 "어느 규칙으로 만든 앱인지"를
알 수 있습니다. 덮어쓸 자리는 `it-guide/web/prompt/index.html` 입니다.

> 볼륨으로 붙여 두었으므로 **덮어쓰고 새로고침만 하면 반영됩니다.**
> 도커 이미지를 다시 만들 필요가 없습니다.
>
> 챗 쪽은 5분까지 옛 내용을 기억할 수 있습니다 (`GUIDE_CACHE_SEC`).
> 급하면 `docker restart portal` 하면 즉시 지워집니다.

## 5. 옛 포털 정리

`/manual/`, `/checklist/`, `/ito-cost/` 가 새 주소로 잘 열리는 것을
확인한 뒤에 옛 것을 내리세요.

```bash
cd ~/it-portal/portal-web
docker compose down          # itportal-web, itportal-asset-api
```

`it-portal/portal-web` 폴더는 지우지 말고 당분간 두시길 권합니다.
원본이 남아 있어야 무언가 어긋났을 때 견줘 볼 수 있습니다.

## 알아둘 것 — 챗이 읽는 방식

포털이 이 앱의 파일을 **HTTP 로 가져와서** 읽습니다. 파일 시스템을
공유하지 않습니다. 그래서 나중에 이 앱을 다른 서버로 옮겨도
`GUIDE_API` 만 바꾸면 그대로 돕니다.

읽는 곳은 두 군데입니다.

```
/manuals/data/manuals.js     window.MANUAL_DATA = { ... }
/checklist/index.html        <script id="app-data"> { ... } </script>
```

두 번째는 화면 파일 안에 데이터가 박혀 있어서 뽑아 씁니다.
**`app-data` 라는 id 가 앱과의 약속입니다.** 나중에 체크리스트 화면을
크게 고칠 일이 있으면 그 id 는 그대로 두세요. 바꾸면 챗이 못 읽습니다.
