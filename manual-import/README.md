# 매뉴얼 가져오기 (manual-import)

PowerPoint 파일을 올리면 IT 매뉴얼로 바꿔 줍니다.

| 항목 | 내용 |
|---|---|
| 서비스 ID | `manual-import` |
| 접속 주소 | `/manual-import/` |
| 컨테이너 | `manual-import` (안쪽 8080, 바깥 포트 없음) |
| 쓰는 사람 | **담당자(admin) 전용** |
| 고치는 대상 | `it-guide/web/manuals/` (볼륨으로 붙어 있음) |

## 왜 만들었나

PPT 를 고치고 매뉴얼 화면에서 또 고치면 **같은 내용을 두 번 관리하게 됩니다.**
두 곳에 같은 내용을 두면 반드시 갈라지므로 한쪽을 원본으로 정했습니다.

> **PPT 가 원본입니다.** 내용을 고칠 일이 생기면 PPT 를 고쳐서 다시 올립니다.
> 매뉴얼 화면의 편집 모드로 고친 것은 다음 업로드 때 덮어써집니다.

## 어떻게 대응시키나

```
PPT 파일 하나        →  매뉴얼 하나
제목이 같은 슬라이드  →  항목(Menu) 하나
슬라이드 한 장       →  그 항목 안의 묶음 하나
슬라이드의 글        →  절차 (steps)
슬라이드의 그림      →  화면 캡처 (images/<id>/02_1.png)
```

- 슬라이드 **제목 자리**의 글이 항목 이름이 됩니다. 제목 자리를 안 썼으면
  **맨 위에 있는 텍스트 상자의 첫 줄**을 제목으로 봅니다.
- **제목이 같은 슬라이드가 이어지면 한 항목으로 묶습니다.** 한 가지 일에
  슬라이드 네 장을 쓰는 건 흔한데, 장마다 항목을 만들면 목차에 같은 이름이
  네 번 찍힙니다. 묶인 장은 미리보기에서 `슬라이드 7·8·9·10장을 묶었습니다`
  로 보여 줍니다.
  - **띄어쓰기와 마침표 차이는 무시합니다.** `Menu 4.SAP` 와 `Menu 4. SAP` 는
    같은 것으로 봅니다.
  - 괄호 안이 다르면(`(운영 서버)` / `(개발 서버)`) 다른 항목입니다.
    묶고 싶으면 PPT 에서 제목을 똑같이 맞추세요.
- 첫 장이 제목뿐이면 **표지로 보고 항목에서 뺍니다.** 그 제목이 매뉴얼
  이름으로 제안됩니다.
- 마지막 장이 `끝`·`감사합니다` 같은 맺음말이면 항목이 아니라
  **매뉴얼 아래 문의 안내**로 들어갑니다.
- 본문 상자 위의 `설명`·`절차` 같은 **이름표 한 낱말은 버립니다.**
  안 그러면 항목마다 "설명" 이라는 절차가 하나씩 생깁니다.
- 표는 `구분 · 연락처` 처럼 한 줄로 폅니다.
- **작은 그림(120px 미만)은 넣지 않습니다.** 로고·아이콘까지 캡처로 들어가면
  매뉴얼이 지저분해집니다.

## PPT 원본은 서버에 남습니다

올린 PPT 는 `it-guide/web/manuals/sources/<id>.pptx` 로 그대로 보관됩니다.
목록의 **PPT 원본 받기** 로 언제든 내려받을 수 있습니다.

> 매뉴얼을 고치려면 원본 PPT 가 있어야 하는데, 그게 만든 사람 PC 에만
> 있으면 그 사람이 없을 때 아무도 못 고칩니다. 받아서 → 고쳐서 → 다시 올리면
> 됩니다.

원본과 백업 폴더는 매뉴얼 화면 쪽에서는 **막혀 있습니다**
(`proxy/apps/manual.conf`). 매뉴얼을 볼 수 있는 사람과 고칠 수 있는 사람은
다르기 때문입니다.

## 매뉴얼 ID 는 알아서 맞춰 줍니다

`1. SAP_GUI_매뉴얼.pptx` 는 `sap-gui` 를 **고치러** 온 파일이지,
`1-sap-gui` 를 새로 만들러 온 파일이 아닙니다. 그래서

- 파일 이름 앞의 순번(`1.`, `2)`)은 떼어 냅니다
- 남은 이름이 기존 매뉴얼 ID 를 품고 있으면 **그 ID 를 먼저 제안**합니다
- 매뉴얼 이름이 기존 것과 같아도 그 ID 를 제안합니다

그래도 화면에서 바꿀 수 있습니다. 새 ID 인지 기존 것을 바꾸는지는
반영 버튼 위에 늘 적혀 있습니다.

## 쓰는 법

1. 포털에서 **매뉴얼 가져오기** 열기
2. `.pptx` 파일을 끌어다 놓기 → **읽은 결과를 먼저 보여줍니다** (아직 안 바뀝니다)
3. 항목 이름·절차가 제대로 잡혔는지 확인. 이상하면 **PPT 쪽을 고치는 편이 낫습니다**
4. 매뉴얼 ID 를 정하고 **매뉴얼에 반영**
   - 기존 ID 를 쓰면 그 매뉴얼을 **통째로 바꿉니다** (화면에서 미리 알려줍니다)
   - 새 ID 면 매뉴얼이 하나 늘어납니다
5. 매뉴얼 화면 새로고침

## 되돌리기

반영 직전에 `it-guide/web/manuals/data/backup/manuals-<날짜>.js` 로 백업합니다.
최근 20개까지 남습니다. 잘못 올렸으면 그 파일을 `data/manuals.js` 로 덮어쓰면 됩니다.

```bash
cd /srv/portal/it-guide/web/manuals/data
ls backup/
cp backup/manuals-20260811-131015.js manuals.js
```

> 그림은 되돌아가지 않습니다. `images/<id>/` 는 새 것으로 덮어써집니다.
> 그림까지 되살려야 하면 옛 PPT 를 다시 올리는 편이 빠릅니다.

## 지우기

목록의 **지우기** 를 누르면 그 매뉴얼의 내용·그림·PPT 원본이 함께 사라집니다.
지우기 전에도 백업을 뜨므로 되돌릴 수는 있습니다(그림은 빼고).
잘못된 ID 로 올려 매뉴얼이 하나 더 생겼을 때 쓰면 됩니다.

## 권한

- 이 앱은 **매뉴얼을 통째로 바꿉니다.** 접근 범위에 든 사람이라도
  **담당자로 지정된 사람만** 반영할 수 있습니다 (`X-User-Role: admin`).
- 포털 관리자 화면 → 서비스 관리 → 매뉴얼 가져오기 → 담당자 지정.
- 접근 범위도 좁게 잡으시길 권합니다. IT 담당자면 충분합니다.

## 알아둘 것

- `.ppt`(옛 형식)는 못 읽습니다. PowerPoint 에서 `.pptx` 로 다시 저장하세요.
- 파일은 60MB 까지. 캡처가 많으면 금방 커집니다.
- 매뉴얼 순서는 **바뀌지 않습니다.** 기존 매뉴얼을 바꿔도 늘 보던 자리에 남습니다.
- 매뉴얼에 적어 둔 **문의 안내(contactNote)는 살립니다.** PPT 에 없는 정보라
  덮어쓰면 사라지기 때문입니다.
- 챗 쪽은 매뉴얼을 5분까지 담아 둡니다(`GUIDE_CACHE_SEC`). 급하면
  `docker restart portal`.
